изменены только четыре её файла (список ниже). Дженерики оставлены.

`putIfAbsent`, `containsKey`, `forEach`, `clear`, `getLoadFactor`, `getAverageProbes`, `getLastProbes`,

## Как это закрывает задание
**Минимум:** вставка/поиск/удаление; панель с перерисовкой после каждой операции и подсветкой посещённых ячеек;
генерация N записей; фоновая загрузка файла через `Task` с прогрессом.
**Средний:** рехеш; статистика проб (в операции, среднее за всё время, путь); генерация в фоне и «Отмена»
(и для загрузки, и для генерации); таблица замеров времени (`HashTableBenchmark`).

## Для отчёта
1. **Замеры:** запусти `HashTableBenchmark.main()` в IDEA (правой кнопкой на файле → Run), 2–3 раза, возьми типичные цифры.
   У меня: на 100 000 записей вставка ≈ 58 мс при ≈ 3.6 пробы, поиск имеющегося ключа ≈ 1.3 пробы.
2. **Асимптотика** (n — число элементов, m — ёмкость, заполнение ≤ 0.75):

| Операция | В среднем | В худшем | Обоснование |
|---|---|---|---|
| put | O(1) | O(n) | в среднем пара проб; в худшем все ключи в одном «кластере» |
| get | O(1) | O(n) | то же |
| remove | O(1) | O(n) | поиск + пометка DELETED |
| рехеш | O(m) | O(m) | все элементы вставляются заново; на одну вставку в среднем O(1), т.к. размер удваивается |
| findAll (обход) | O(m) | O(m) | проход по всем ячейкам |

## Что проверено, что нет

занятие ячейки, отрицательные ключи), сервис на настоящем `batches.csv`, обе задачи (прогресс, отмена,
отсутствующий файл), экспорт в CSV и обратная загрузка, замеры, `HashTableView` на заглушках JavaFX.

что-то подсветится красным, пришли текст ошибки.
